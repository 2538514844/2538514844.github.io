## [no_ai_slop_writing_rules](https://github.com/realrossmanngroup/no_ai_slop_writing_rules) #1

> 针对AI写作中常见的“slop”腔调，该仓库提供了一套可编程的规则集，帮助开发者或用户定制提示词，减少“delve”“it’s important to note”等AI惯用语。社区围绕“如何让AI更像人类”展开了激烈讨论。

<p><img src="https://opengraph.githubassets.com/1/realrossmanngroup/no_ai_slop_writing_rules" alt="no_ai_slop_writing_rules" style="max-width:100%;border-radius:8px;"></p>

越来越多的创作者抱怨AI生成文本千篇一律，缺乏真实表达。**no_ai_slop_writing_rules** 由 **realrossmanngroup** 发起，通过列举具体禁止使用的词汇和句式，试图规范输出风格。

项目核心是一份 Markdown 规则清单，涵盖词汇、句法和结构层面的注意事项。用户可直接将其粘贴到系统提示词中，或用作 **Claude**、**ChatGPT** 的 `system_prompt`，以抑制模型默认的“热情客服”语气。

截至发稿，该项目获得 **152 Stars** 和 **11 Forks**，在 **Hacker News** 和 **Reddit** 上引发了两极化讨论。支持者认为这是实用指南，批评者则指出规则过于主观，可能抹杀模型创造性。

值得注意的是，仓库同时提供了中文译本，兼容不同语言写作场景。与同类项目如 **"Anti-AI Writing"** 相比，它更强调可操作性，而非纯理论批判。适合内容创作者、提示词工程师和关注 AI 输出质量的团队参考。

- 项目地址：[realrossmanngroup/no_ai_slop_writing_rules](https://github.com/realrossmanngroup/no_ai_slop_writing_rules)

## [LCE-Emerald-Launcher](https://github.com/lceminecraft-launcher/LCE-Emerald-Launcher) #2

> 针对 Minecraft 基岩版 LCE 启动器功能匮乏的问题，Emerald 启动器提供了版本隔离、模组管理和自定义存档支持。项目使用 **TypeScript** 与 **Electron** 构建，面向需要在老旧或特殊版本上游玩的玩家。

<p><img src="https://opengraph.githubassets.com/1/lceminecraft-launcher/LCE-Emerald-Launcher" alt="LCE-Emerald-Launcher" style="max-width:100%;border-radius:8px;"></p>

Minecraft 基岩版（LCE）近年来停止了官方更新，但仍有大量玩家停留在特定版本。社区需要一款能够绕过启动器限制、自由切换版本的工具，**LCE-Emerald-Launcher** 正是在此背景下诞生。

该启动器采用 **TypeScript** 编写，利用 **Electron** 构建跨平台界面。核心功能包括多个 **LCE 版本** 的下载与独立部署、模组注入、以及存档管理。其架构借鉴了 **PolyMC** 的设计，但聚焦于基岩版。

目前 **Stars** 数 **90**，**Forks** 为 **0**，表明项目尚在早期阶段。开发者表示支持 Windows 和 Linux，并提供预编译二进制。不过由于涉及破解版本，用户需自行承担合规风险。

与官方启动器相比，Emerald 允许用户自定义 Java 路径和内存分配，并集成了 **ModLoader** 接口。适用于需要同时维护多个版本或运行过期模组的玩家。

- 项目地址：[lceminecraft-launcher/LCE-Emerald-Launcher](https://github.com/lceminecraft-launcher/LCE-Emerald-Launcher)

## [cursor_agent_status_light](https://github.com/JasonLam08/cursor_agent_status_light) #3

> 一款基于 **C++** 的 USB 状态指示灯硬件方案，通过 RGB LED 实时反映 **Cursor** 中 AI Agent 的处理状态。当 Agent 执行任务时灯光闪烁，空闲时保持常亮，帮助开发者避免无效等待。

<p><img src="https://opengraph.githubassets.com/1/JasonLam08/cursor_agent_status_light" alt="cursor_agent_status_light" style="max-width:100%;border-radius:8px;"></p>

使用 **Cursor** 编辑器时，AI Agent 在后台进行代码生成或调试，用户往往难以感知其活动状态。**cursor_agent_status_light** 提供了一种物理反馈机制，将软件状态映射为可视光信号。

项目采用 **C++** 编写控制固件，兼容 **Arduino** 和 **STM32** 系列微控制器。通过 USB 串口与 Cursor 的插件通信，接收当前 Agent 状态（空闲、忙碌、错误），并驱动 **WS2812B RGB LED** 显示对应颜色。

该项目获得 **53 Stars** 和 **6 Forks**，社区提供了详细的硬件清单和 3D 打印外壳文件。目前支持 macOS 和 Windows，但 Linux 版本正在开发中。

与同类软件方案（如系统托盘图标）不同，物理指示灯更适合多显示器或全屏场景。用户可根据个人喜好自定义颜色映射，例如红色代表错误，蓝色代表处理中。

- 项目地址：[JasonLam08/cursor_agent_status_light](https://github.com/JasonLam08/cursor_agent_status_light)

## [claude-writing-skills](https://github.com/xiaomoBoy/claude-writing-skills) #4

> 专为 **Claude** 模型整理的写作技巧提示词库，包含故事叙述、学术论文、营销文案等场景的系统提示词，利用 Claude 的长上下文优势提升输出质量。项目附带 Python 脚本用于测试和批量生成。

<p><img src="https://opengraph.githubassets.com/1/xiaomoBoy/claude-writing-skills" alt="claude-writing-skills" style="max-width:100%;border-radius:8px;"></p>

Claude 在长文写作中表现突出，但许多用户不知道如何编写有效的提示词以发挥其潜力。**claude-writing-skills** 由 **xiaomoBoy** 创建，旨在收集并标准化经过验证的写作提示模板。

仓库以 Markdown 格式提供数十个分类提示词，涵盖“角色设定”“冲突构建”“论点递进”等技巧，所有提示词均针对 **Claude 3.5 Sonnet** 和 **Opus** 模型优化。同时提供一个 **Python** 脚本，通过 API 自动测试不同提示词的输出效果。

当前 **Stars** 为 **21**，**Forks** 为 **1**，属于小型但实用的资源库。项目还在持续更新，计划加入更多中式写作场景的提示词。

与通用提示词库（如 **awesome-claude-prompts**）相比，该项目更聚焦于写作技法本身，而非任务类型。适合作家、学生和内容营销人员作为参考工具。

- 项目地址：[xiaomoBoy/claude-writing-skills](https://github.com/xiaomoBoy/claude-writing-skills)

## [mero-compiler](https://github.com/6x-u/mero-compiler) #5

> 一个教学性质的迷你编译器，使用 **C++** 实现了从类 C 语言子集到 **x86** 汇编代码的完整编译流程，包含词法分析、语法分析、中间代码生成和目标代码生成。

<p><img src="https://opengraph.githubassets.com/1/6x-u/mero-compiler" alt="mero-compiler" style="max-width:100%;border-radius:8px;"></p>

编译器原理是计算机科学的核心课程，但很少有项目能提供足够简洁且可运行的参考实现。**mero-compiler** 由个人开发者 **6x-u** 编写，旨在用不到 **2000 行 C++ 代码** 演示编译器基本流程。

项目目前支持整数运算、变量声明、条件分支（`if-else`）和循环（`while`），输出 **x86-64** 汇编文件。采用递归下降语法分析，并生成三地址码作为中间表示。

虽然 **Stars** 仅 **12**，但代码结构清晰，注释详尽，适合编译原理初学者对照教材学习。开发者计划未来加入函数定义和指针操作。

同类项目如 **tcc** 追求完整性和性能，而 **mero-compiler** 则偏向教学透明性。读者可以通过阅读源码理解从词法到目标代码的每一步转换。

- 项目地址：[6x-u/mero-compiler](https://github.com/6x-u/mero-compiler)
