## [MiniMax-AI/MSA](https://github.com/MiniMax-AI/MSA) #1

> **MiniMax** 开源的 **多智能体系统（MSA）** 框架，提供轻量级、可扩展的智能体协作范式，让开发者能快速构建多 Agent 应用。该框架设计简洁，支持任务编排、记忆和通信，适合研究人员和工业部署。

<p><img src="https://opengraph.githubassets.com/1/MiniMax-AI/MSA" alt="MiniMax-AI/MSA" style="max-width:100%;border-radius:8px;"></p>

多智能体系统（MAS）是当前 AI 主流方向之一，但现有框架往往过于复杂或绑定特定底层模型。**MiniMax** 推出 **MSA** 正是为了解决这些痛点，降低开发者入门门槛，同时保持灵活性。

**MSA** 采用模块化架构，核心组件包括 Agent 调度器、消息总线和共享记忆。开发者只需定义 Agent 角色与任务，框架自动处理协作推理、结果聚合与异常恢复。内置支持 **MiniMax** 自家模型及第三方 API。

目前仓库获得 112 Stars 和 10 Forks，社区关注度持续上升。官方提供了多个示例，包括代码编写、数据分析和游戏 Agent，帮助用户快速上手。与 **LangChain** 等工具相比，**MSA** 更聚焦多 Agent 交互本身，不提供过多外部集成。

## [joeseesun/qiaomu-goal-meta-skill](https://github.com/joeseesun/qiaomu-goal-meta-skill) #2

> **乔木目标元技能** 是一个基于 **Python** 的元学习实验框架，旨在让 AI 模型学会“如何学习”，特别是针对多目标优化场景。它通过分解复杂目标为子技能，并动态组合来完成从未见过的任务。

<p><img src="https://opengraph.githubassets.com/1/joeseesun/qiaomu-goal-meta-skill" alt="joeseesun/qiaomu-goal-meta-skill" style="max-width:100%;border-radius:8px;"></p>

目前多数强化学习或元学习方法只关注单一最终奖励，但现实世界需要平衡多个目标。**qiaomu-goal-meta-skill** 提出一种新颖的元技能编码机制，将每个子目标映射为可复用的 skill 向量，然后通过注意力网络自适应组合。

核心功能包括：多目标奖励分解、skill 库增量更新、跨任务泛化验证。框架支持 **PyTorch** 后端，并提供评估环境集合（连续控制、导航等）。项目目前有 107 Stars，活跃贡献者来自国内高校。

与 **Meta-World**、**MAML** 等经典方法相比，该方案在任务切换时无需重新训练整个网络，只需更新 skill 组合权重，计算效率提升明显。实验表明在 **ML10** 和 **ML45** 基准上收敛速度提高 30% 以上。

相关链接：
- 项目地址：[joeseesun/qiaomu-goal-meta-skill](https://github.com/joeseesun/qiaomu-goal-meta-skill)

## [pseudoku/Kotinos](https://github.com/pseudoku/Kotinos) #3

> **Kotinos** 是一款基于 **OpenSCAD** 的参数化 3D 零件生成器，专门用于创建可定制的外壳、支架和机械连接件。它提供丰富的预设模板，用户只需调整参数即可导出高精度模型，无需手动建模。

<p><img src="https://opengraph.githubassets.com/1/pseudoku/Kotinos" alt="pseudoku/Kotinos" style="max-width:100%;border-radius:8px;"></p>

对于创客和3D打印爱好者，重复设计标准零件十分耗时。**Kotinos** 的出现将这类工作完全参数化：所有尺寸、倒角、孔位等属性均通过变量控制，修改参数立即可见预览并生成 STL/SCAD 文件。

项目内置分型模块：可用于盒子、电池仓、PCB 支架、树莓派外壳等。同时支持布尔运算组合，已有 64 Stars，3 Forks。代码完全开源，贡献者可通过 **OpenSCAD** 语言扩展新模板。

与 **Thingiverse** 上的逐个下载不同，**Kotinos** 强调“设计即代码”，参数修改后自动适应配合公差，大幅减少迭代试错。社区用户反馈其在制作无人机机架和机器人底盘时节省了数小时建模时间。

相关链接：
- 项目地址：[pseudoku/Kotinos](https://github.com/pseudoku/Kotinos)

## [Sliverkiss/mimocode2api](https://github.com/Sliverkiss/mimocode2api) #4

> **mimocode2api** 是一个 **Go** 编写的小工具，能将一段微型代码片段快速封装成 HTTP API 接口。用户只需提供输入输出描述和核心逻辑代码，工具自动生成带参数校验、错误处理、跨域支持的 API 服务。

<p><img src="https://opengraph.githubassets.com/1/Sliverkiss/mimocode2api" alt="Sliverkiss/mimocode2api" style="max-width:100%;border-radius:8px;"></p>

在日常开发中，临时需要将某个算法或数据处理逻辑暴露为接口时，往往需要编写大量胶水代码。**mimocode2api** 瞄准这一场景，通过定义 YAML 配置文件和一段 Go 函数体，即可启动一个标准化 HTTP 服务。

核心特性包括：自动生成 Swagger 文档、支持 GET/POST 方法、内置限流与日志。项目当前 37 Stars，5 Forks，代码简洁易读。开发者可将其用于微服务敏捷原型、数据预处理 API 或模型推理服务桥接。

对比同类产品（如 **OpenFaaS**、**AWS Lambda**），**mimocode2api** 更轻量，无需容器化或云函数环境，特别适合本地调试和边缘设备部署。但仅限 Go 语言编写代码片段。

相关链接：
- 项目地址：[Sliverkiss/mimocode2api](https://github.com/Sliverkiss/mimocode2api)

## [TheAceOfficials/BetterPoster-for-Jellyfin](https://github.com/TheAceOfficials/BetterPoster-for-Jellyfin) #5

> **BetterPoster for Jellyfin** 是一个 **C#** 插件，为 **Jellyfin** 媒体服务器提供高清、动态的多语言海报展示，支持自动刮削元数据后生成艺术字标题和定制背景。

<p><img src="https://opengraph.githubassets.com/1/TheAceOfficials/BetterPoster-for-Jellyfin" alt="TheAceOfficials/BetterPoster-for-Jellyfin" style="max-width:100%;border-radius:8px;"></p>

Jellyfin 原生海报仅是普通图片，缺乏文字信息及弹性布局。**BetterPoster** 插件通过后端渲染引擎，根据电影/剧集的元数据（标题、评分、年份、类型）实时合成海报，完全替换原图显示。

支持多种主题风格（极简、复古、IMDb 式），用户可自定义字体、颜色和布局。安装后自动扫描现有媒体库，生成缓存海报。目前 27 Stars，1 Fork，代码托管在 GitHub。开发者承诺不修改 Jellyfin 核心代码，兼容所有版本。

与 **Plex** 的漂亮海报相比，**Jellyfin** 用户一直缺少开箱即用的美化方案。**BetterPoster** 填补了这一空白。实测在 4K 设备上渲染速度小于 500ms，对性能影响极小。

相关链接：
- 项目地址：[TheAceOfficials/BetterPoster-for-Jellyfin](https://github.com/TheAceOfficials/BetterPoster-for-Jellyfin)

## [oy-paddy/aliyun-model-proxy](https://github.com/oy-paddy/aliyun-model-proxy) #6

> **aliyun-model-proxy** 是一个 **TypeScript** 编写的轻量级代理服务，专门用于透明转发、鉴权和负载均衡 **阿里云通义千问** 等大模型 API 请求。支持多 API Key 轮换、请求速度控制和响应缓存。

<p><img src="https://opengraph.githubassets.com/1/oy-paddy/aliyun-model-proxy" alt="oy-paddy/aliyun-model-proxy" style="max-width:100%;border-radius:8px;"></p>

企业在调用阿里云大模型时，常面临 API Key 成本管理、调用频率限制、多个模型切换等问题。**aliyun-model-proxy** 提供了一个中间层，拦截原始请求，按策略路由到不同模型或 Key，并记录调用日志。

核心能力包括：基于 Token 的限流、失败重试、自定义 Prompt 预处理。支持 **DashScope** SDK 兼容模式，客户端无需修改代码。项目目前 20 Stars，1 Fork，适合中小团队快速部署。

与 **Kong**、**APISIX** 等通用网关相比，该代理专为阿里云模型优化，代码量仅数百行，易于审计和定制。开发者在 README 中强调“只做代理，不做魔法”，保证透明与安全。

相关链接：
- 项目地址：[oy-paddy/aliyun-model-proxy](https://github.com/oy-paddy/aliyun-model-proxy)

## [ahXN00/OwnTV](https://github.com/ahXN00/OwnTV) #7

> **OwnTV** 是一个基于 **Kotlin** 开发的自定义电视直播应用，专为 **Android TV** 设计。用户可导入 M3U 播放源、EPG 节目单，并享受无广告、可定制的原生电视体验。

<p><img src="https://opengraph.githubassets.com/1/ahXN00/OwnTV" alt="ahXN00/OwnTV" style="max-width:100%;border-radius:8px;"></p>

随着传统电视逐渐转向 IPTV，许多用户需要一款干净、开源的客户端来管理自己的频道源。**OwnTV** 定位为替代商业应用（如 **TiviMate**），提供完全本地化、无追踪的播放体验。

主要功能：M3U 播放列表导入、EPG 解析（XMLTV）、频道收藏、分组管理、多音轨/字幕支持。界面遵循 Material Design 3，支持 Leanback 导航。目前 19 Stars，0 Fork，仍在早期开发阶段，但已可稳定播放主流源。

代码采用 **Jetpack Compose for TV** 编写，模块化架构方便二次开发。相比 **Kodi** 的庞大，**OwnTV** 轻量且专注于电视直播场景。计划未来加入录制和回看功能。

相关链接：
- 项目地址：[ahXN00/OwnTV](https://github.com/ahXN00/OwnTV)
