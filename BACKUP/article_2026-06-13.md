## [ponytail](https://github.com/DietrichGebert/ponytail) #1

> 一个基于 Node.js 的无头浏览器自动化工具，让 Puppeteer 和 Playwright 脚本以「马尾辫」般的轻量方式运行。它提供统一 API，大幅降低调试和维护成本。

项目背景是现有浏览器自动化工具配置繁琐、脚本复用困难。**ponytail** 由开发者 **DietrichGebert** 创建，旨在将 Playwright 与 Puppeteer 的调用封装为一个简洁的 CLI 和 Node.js 模块。

<p><img src="https://opengraph.githubassets.com/1/DietrichGebert/ponytail" alt="ponytail" style="max-width:100%;border-radius:8px;"></p>

核心功能包括自动下载浏览器、智能等待元素加载、以及报告生成。它支持脚本热重载，开发过程中无需重复启动浏览器。目前获得 **958 Stars** 和 **44 Forks**，社区关注度持续上升。

与同类项目相比，ponytail 的「零配置」理念更适合快速原型验证。它内置了常见异常处理逻辑，例如页面超时自动重试。推荐用于持续集成中的 E2E 测试和网页数据抓取。

相关链接：
- 项目地址：[DietrichGebert/ponytail](https://github.com/DietrichGebert/ponytail)

## [compose-nav-graph](https://github.com/skydoves/compose-nav-graph) #2

> 一个为 **Jetpack Compose** 打造的声明式导航图库，用 `NavGraphBuilder` 扩展函数优雅定义路由，无需 XML 配置文件。它让多页面应用的导航逻辑一目了然。

Android 原生导航在 Compose 中常导致页面间耦合度高。**skydoves** 团队推出的 **compose-nav-graph** 借鉴了 Navigation Compose 的 DSL 思想，但提供了更直观的语法糖。

<p><img src="https://opengraph.githubassets.com/1/skydoves/compose-nav-graph" alt="compose-nav-graph" style="max-width:100%;border-radius:8px;"></p>

该库支持参数类型安全传递、嵌套导航图以及深度链接。开发者只需使用 `composable` 和 `navigation` 扩展函数即可完成路由配置。当前收获 **179 Stars** 和 **4 Forks**，在 Kotlin 社区引起讨论。

与官方库相比，compose-nav-graph 减少了样板代码，并内置了动画过渡支持。它特别适合中大型 Compose 项目的页面管理，例如电商应用的多级分类页。

相关链接：
- 项目地址：[skydoves/compose-nav-graph](https://github.com/skydoves/compose-nav-graph)

## [architect-loop](https://github.com/DanMcInerney/architect-loop) #3

> 一个由 AI 驱动的「架构循环」工具，自动迭代生成建筑平面图与结构设计。它将 LLM 与物理约束结合，让非专业人士也能快速获得合规的房屋布局方案。

传统建筑设计依赖专业软件和大量手动调整。**DanMcInerney** 开发的 **architect-loop** 利用大语言模型理解用户需求（如房间数量、面积），通过循环反馈优化平面图。

<p><img src="https://opengraph.githubassets.com/1/DanMcInerney/architect-loop" alt="architect-loop" style="max-width:100%;border-radius:8px;"></p>

技术方案包括：使用 **OpenAI API** 生成初始布局，然后调用几何库进行碰撞检测与承重校验。若方案不合格，AI 会重新生成直至满足规则。GitHub 上已有 **171 Stars** 和 **10 Forks**。

适用场景包括个人建房前期规划、室内设计快速提案。区别于其他 AI 绘图工具（如 Midjourney），architect-loop 输出的是带尺寸标注的矢量图，可直接用于施工图参考。

相关链接：
- 项目地址：[DanMcInerney/architect-loop](https://github.com/DanMcInerney/architect-loop)

## [renwei-writing](https://github.com/orange2ai/renwei-writing) #4

> 一个面向长文写作的 AI 辅助平台，支持从大纲生成到逐段润色。它内置多种写作风格（学术、小说、商业文案），可导出为 Markdown/Word/PDF。

当前写作工具多聚焦短内容，对长文档的结构化管理不足。**orange2ai** 推出的 **renwei-writing** 通过划分章节、段落级 AI 建议来提升写作效率。

<p><img src="https://opengraph.githubassets.com/1/orange2ai/renwei-writing" alt="renwei-writing" style="max-width:100%;border-radius:8px;"></p>

核心功能包括：智能大纲生成、段落连贯性检查、以及引用文献自动格式化。它支持多人协作编辑，并保留版本历史。目前获得 **114 Stars** 和 **10 Forks**，项目仍处于早期开发阶段。

与 Notion AI 或 Grammarly 相比，renwei-writing 对长文的分拆迭代能力更强。例如，写论文时可锁定关键论点，让 AI 只修改表述。适合学生、自媒体作者和内容策划团队。

相关链接：
- 项目地址：[orange2ai/renwei-writing](https://github.com/orange2ai/renwei-writing)

## [xhs-article-to-images](https://github.com/bozhouDev/xhs-article-to-images) #5

> 将小红书「图文笔记」一键转换为社交分享图片，保留原排版与表情符号。支持自定义背景、字体和卡片尺寸，适配朋友圈、微博等平台。

小红书内容以富文本和表情搭配为特色，直接截图会丢失交互感。**bozhouDev** 开发的 **xhs-article-to-images** 解析文章结构，用 CSS 渲染出精美图片。

<p><img src="https://opengraph.githubassets.com/1/bozhouDev/xhs-article-to-images" alt="xhs-article-to-images" style="max-width:100%;border-radius:8px;"></p>

核心实现基于 `html2canvas` 和 `dom-to-image`，支持批量转换。用户只需粘贴链接或文本，即可在浏览器中生成下载按钮。该项目拥有 **52 Stars** 和 **7 Forks**。

使用场景包括：小红书博主将笔记同步到其他平台时保持风格统一；品牌方快速制作营销素材。与同类工具相比，它保留了小红书的圆角卡片和标签样式。

相关链接：
- 项目地址：[bozhouDev/xhs-article-to-images](https://github.com/bozhouDev/xhs-article-to-images)

## [fable5-world-demo](https://github.com/Braffolk/fable5-world-demo) #6

> 一个基于 TypeScript 的互动故事引擎，允许创作者构建动态世界、角色和分支剧情。它采用事件驱动的叙事逻辑，类似文字冒险游戏的升级版。

传统互动小说工具多依赖硬编码选择分支，扩展性差。**Braffolk** 开发的 **fable5-world-demo** 将世界状态持久化，角色行为根据玩家决策实时变化。

<p><img src="https://opengraph.githubassets.com/1/Braffolk/fable5-world-demo" alt="fable5-world-demo" style="max-width:100%;border-radius:8px;"></p>

技术栈使用 **React** 前端与 **Node.js** 后端，剧情以 JSON 格式定义。它支持随机事件、资源管理和角色属性系统。当前获得 **48 Stars** 和 **10 Forks**。

该 demo 展示了如何用少量代码实现《克苏鲁的呼唤》式叙事。对独立游戏开发者而言，fable5-world-demo 提供了一个可定制的基础框架。未来计划加入 AI 生成的对话内容。

相关链接：
- 项目地址：[Braffolk/fable5-world-demo](https://github.com/Braffolk/fable5-world-demo)

## [open-dungeon](https://github.com/newideas99/open-dungeon) #7

> 一个开源的随机地牢生成器，使用程序化算法创建俯视角地图、怪物分布和宝物刷出点。支持自定义种子和难度参数，适合 RPG 游戏开发快速原型。

很多独立游戏需要随机地图来提升重玩性，但手写算法门槛高。**newideas99** 推出的 **open-dungeon** 提供了基于 `BSP` 和 `A*` 的生成管线，输出可直接用于 Unity/Godot。

<p><img src="https://opengraph.githubassets.com/1/newideas99/open-dungeon" alt="open-dungeon" style="max-width:100%;border-radius:8px;"></p>

项目用 TypeScript 编写，附带可交互的 Web 演示。玩家可调整房间大小、走廊宽度和怪物密度。GitHub 上已有 **48 Stars** 和 **3 Forks**。

与 TinyKeep 等商业工具相比，open-dungeon 完全开源且可嵌入。开发者只需引入一个 npm 包，即可在游戏中生成符合规则的地下城。后续计划加入陷阱和宝箱逻辑。

相关链接：
- 项目地址：[newideas99/open-dungeon](https://github.com/newideas99/open-dungeon)
