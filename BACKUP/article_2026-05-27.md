## [make-pages-interactive](https://github.com/paraschopra/make-pages-interactive) #1

> 一个轻量级 JavaScript 库，允许开发者通过简单的属性标记将任意 HTML 页面转换为可拖拽、可点击的交互式文档。无需重写现有代码即可增强静态内容的交互性。

**Paras Chopra** 发布该项目时提到，许多团队在维护文档或演示页面时面临“静态内容无法即时演示”的痛点。传统的交互方案往往需要引入复杂框架，而 **make-pages-interactive** 提供了一种渐进增强的解决思路。

核心实现基于 **MutationObserver** 监听 DOM 变化，并通过自定义 `data-interactive` 属性触发拖拽、缩放、点击高亮等事件。库体积仅 **3KB**，不依赖任何第三方运行时，开箱即用。

<p><img src="https://opengraph.githubassets.com/1/paraschopra/make-pages-interactive" alt="make-pages-interactive" style="max-width:100%;border-radius:8px;"></p>

目前该项目在 GitHub 上获得 **125 Stars** 和 **18 Forks**，社区反馈集中于“教学演示”和“原型快速验证”场景。与同类工具如 `html2canvas` 相比，它更专注于实时交互而非截图生成。

对于需要将技术文档、产品手册快速变为可体验原型的团队，该工具能显著减少开发成本。作者计划后续支持触摸事件和自定义回调函数。

相关链接：

## [plan-tree](https://github.com/SeemSeam/plan-tree) #2

> 一个以树状图形式组织项目计划的协作工具，允许用户将目标拆解为可追踪的子任务，并可视化依赖关系。适用于敏捷开发和个人项目管理。

现代项目管理中，传统的甘特图和看板视图无法直观展示任务间的层级关系。**plan-tree** 采用树形结构，每个节点可包含描述、时间估计和负责人，分支可折叠或展开。

<p><img src="https://opengraph.githubassets.com/1/SeemSeam/plan-tree" alt="plan-tree" style="max-width:100%;border-radius:8px;"></p>

该项目使用纯前端实现，数据存储在本地 **LocalStorage**，同时提供导出 JSON 和 Markdown 功能。**42 Stars** 和 **5 Forks** 表明它尚处于早期阶段，但其设计思路引起了少部分项目管理者的兴趣。

与 Notion 或 Obsidian 的插件不同，plan-tree 专为“树形分解”而生，没有多余的功能冗余。如果后续集成云端同步与多人协作，有望成为小型团队的轻量规划利器。

相关链接：
- 项目地址：[SeemSeam/plan-tree](https://github.com/SeemSeam/plan-tree)

## [Neurodesk-AI-dashboard](https://github.com/Abrahamhannah/Neurodesk-AI-dashboard) #3

> 一个基于 CSS 和 Web 组件构建的神经科学 AI 分析仪表盘，整合了 **Neurodesk** 环境中的多个 AI 模型，用于脑影像数据分析与可视化。

神经科学领域的研究者面对 MRI 等海量数据时，常需在多个命令行工具之间切换。**Neurodesk-AI-dashboard** 提供统一的图形界面，封装了 `fMRIPrep`、`SPM` 等经典工具，并通过后端 API 调用 AI 模型进行自动分割和分类。

<p><img src="https://opengraph.githubassets.com/1/Abrahamhannah/Neurodesk-AI-dashboard" alt="Neurodesk-AI-dashboard" style="max-width:100%;border-radius:8px;"></p>

项目目前 **32 Stars**，尚无可用的 Release，但其代码结构体现了“微前端”思想：每个功能模块独立为 Web Component。它针对的 **Neurodesk** 用户群体（约十万级）具有明确的痛点，如果能完善部署文档，可能吸引更多研究者。

相较于 **BrainLife** 等云平台，该仪表盘专注于本地化部署，保证数据隐私。目前限制在于仅支持 Linux 环境，且依赖 **Docker** 镜像。

相关链接：
- 项目地址：[Abrahamhannah/Neurodesk-AI-dashboard](https://github.com/Abrahamhannah/Neurodesk-AI-dashboard)

## [MobileAgent-Android](https://github.com/GiggleWang/MobileAgent-Android) #4

> 一个在 Android 设备上运行的轻量 AI Agent 框架，支持通过自然语言指令执行手机操作，如拨打电话、发送消息、启动应用等。

随着 **LLM** 在移动端的部署需求增长，**MobileAgent-Android** 尝试将 Agent 能力下沉到本地。它基于 **Kotlin** 编写，利用 Android 的 **AccessibilityService** 实现 UI 交互，核心决策模型默认使用 **Ollama** 本地推理。

<p><img src="https://opengraph.githubassets.com/1/GiggleWang/MobileAgent-Android" alt="MobileAgent-Android" style="max-width:100%;border-radius:8px;"></p>

该项目 **24 Stars** 和 **2 Forks**，目前处于概念验证阶段。与其他移动端 Agent 方案（如 **Auto.js** 插件）相比，其优势在于通过 LLM 理解语义，而非简单的脚本匹配。

开发者 **GiggleWang** 指出，后续将集成 **Android 14** 的新 API 以减少无障碍权限依赖。若性能优化至端侧，可应用于智能助手或自动化测试领域。

相关链接：
- 项目地址：[GiggleWang/MobileAgent-Android](https://github.com/GiggleWang/MobileAgent-Android)

## [Claude-Mythos-AI-Anthropic-App](https://github.com/zhristophe/Claude-Mythos-AI-Anthropic-App) #5

> 一款利用 **Anthropic Claude** API 生成神话风格叙事片段的 Web 应用，用户输入关键词即可获得带有角色、情节和环境描写的短故事。

AI 生成内容（AIGC）在创意写作领域越来越受欢迎，**Claude-Mythos-AI** 专注于“神话”这一特定主题，提供预设的 prompt 模板和风格参数。前端基于 **TypeScript** 和 **React** 构建，后端通过 serverless 函数调用 Claude API。

<p><img src="https://opengraph.githubassets.com/1/zhristophe/Claude-Mythos-AI-Anthropic-App" alt="Claude-Mythos-AI-Anthropic-App" style="max-width:100%;border-radius:8px;"></p>

社区目前 **22 Stars**，虽然用户量小，但代码结构清晰，便于二次开发。作者 **zhristophe** 提供了完整的 **Vercel** 部署指南，并开放了 prompt 工程细节。

与 **GPT Story Generator** 等通用工具相比，该应用通过限制输出风格获得了更高的叙事一致性。缺点是 Claude API 的速率限制可能影响体验，但对个人创作者而言足够使用。

相关链接：
- 项目地址：[zhristophe/Claude-Mythos-AI-Anthropic-App](https://github.com/zhristophe/Claude-Mythos-AI-Anthropic-App)

## [wechat-radar](https://github.com/zjp1997720/wechat-radar) #6

> 一款针对微信的用户关系探测工具，能够扫描附近微信用户并绘制社交关系图谱。因涉及隐私问题，该项目 Star 数仅 16 却拥有高达 **4813 Forks**，暗示其被大量用于分叉和二次开发。

微信生态中，部分营销或安全研究人员试图获取周边用户的基本信息。**wechat-radar** 利用 Android 设备的 **WiFi P2P** 和蓝牙广播发现附近微信设备，无需 root 权限即可获取昵称、头像等公开数据。

<p><img src="https://opengraph.githubassets.com/1/zjp1997720/wechat-radar" alt="wechat-radar" style="max-width:100%;border-radius:8px;"></p>

该仓库的 Star/Forks 比（0.003）极不寻常，通常意味着原始仓库已被封禁或删除，大量 fork 者将其作为基础代码进行修改。目前主仓库仅有零星更新，但 fork 出的多个变体继续在社区传播。

需要指出的是，该工具可能违反 **微信软件许可及服务协议**，用于商业骚扰或侵犯隐私存在法律风险。建议开发者仅在合规研究场景下使用。
