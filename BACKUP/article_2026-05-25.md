## [comimi](https://github.com/yui540/comimi) #1

> 由日本插画师 **yui540** 开发的动漫角色桌面助手，基于 **TypeScript** 构建，可驻留屏幕并响应简单指令。项目以极简交互和精美画风吸引大量关注。 🏆

<p><img src="https://opengraph.githubassets.com/1/yui540/comimi" alt="comimi" style="max-width:100%;border-radius:8px;"></p>

**yui540** 在个人社交账号上多次展示过原创角色设计，**comimi** 是其首个开源软件尝试，旨在让虚拟角色突破静态插画，成为桌面互动伴侣。

项目采用 **Electron + Vite** 技术栈，角色使用 **Canvas** 实时渲染，支持点击反馈、拖拽和简单文本输入。据开发者介绍，后续计划接入语音识别接口。

GitHub 上线两天即收获 **181** 个 **Star** 与 **2** 个 **Fork**，在动漫开发社区迅速传播。当前仅提供 **Windows** 与 **macOS** 打包安装包。

与同类项目如 **虚拟桌宠** 不同，**comimi** 强调“少即是多”——不内置复杂状态机，而是预留 **WebSocket** 插件机制，允许第三方开发者扩展对话剧本。

相关链接：
- 项目地址：[yui540/comimi](https://github.com/yui540/comimi)

## [gepa-viz](https://github.com/modaic-ai/gepa-viz) #2

> 专为 **基因表达式编程（GEP）** 算法设计的交互式可视化工具，支持模型结构实时观察与超参数调试。项目由 **modaic-ai** 团队开源，定位教学与科研辅助。

<p><img src="https://opengraph.githubassets.com/1/modaic-ai/gepa-viz" alt="gepa-viz" style="max-width:100%;border-radius:8px;"></p>

**GEP** 算法在符号回归等领域表现突出，但调试过程常因缺乏可视界面而低效。**gepa-viz** 诞生于作者攻读硕士期间，目标是让算法运行过程“看得见”。

工具核心采用 **D3.js** 渲染表达式树，支持单步执行、种群进化动画和适应度曲线动态绘制。后端使用 **Python** 的 `gepa` 库作为计算引擎，前后端通过 **WebSocket** 通信。

目前获得 **156** 个 **Star** 与 **11** 个 **Fork**，社区反馈集中在教学场景——教师可将其用于课堂演示基因编程过程。已收录于 **modaic-ai** 组织的官方教程仓库。

与 **DEAP** 框架自带的静态绘图不同，**gepa-viz** 允许用户拖拽调整参数后立即重跑进化流程，显著降低了实验迭代周期。

相关链接：
- 项目地址：[modaic-ai/gepa-viz](https://github.com/modaic-ai/gepa-viz)

## [Windows-Xbox-Mode](https://github.com/XboxMode/Windows-Xbox-Mode) #3

> 一款 **C#** 开发的开源工具，能将 **Windows 10/11** 的桌面界面模拟为 **Xbox Series X|S** 主菜单布局。项目获得 **Xbox** 玩家社群的热烈关注。

<p><img src="https://opengraph.githubassets.com/1/XboxMode/Windows-Xbox-Mode" alt="Windows-Xbox-Mode" style="max-width:100%;border-radius:8px;"></p>

许多玩家希望在 **PC** 上获得类似主机的一致体验，但 **Windows** 原生界面与 **Xbox** 应用割裂感明显。开发者 **XboxMode** 试图通过修改 **Explorer** 行为来弥合差异。

工具通过 **Windows API** 劫持任务栏和开始菜单，替换为自定义 **WPF** 控件，并集成最近的游戏快捷方式、Xbox Game Pass 推荐和好友动态。不修改系统文件，卸载后即可还原。

上线后获 **131** 个 **Star**，尽管 **Forks** 为 **0**（可能因项目成熟度较高），但在 **Reddit** 的 `r/pcmasterrace` 板块引发过千讨论。

当前版本仅支持 **Windows 11 23H2+**，未来计划添加自定义主题色和第三方启动器联动。

相关链接：
- 项目地址：[XboxMode/Windows-Xbox-Mode](https://github.com/XboxMode/Windows-Xbox-Mode)

## [Todo-Tree-Next](https://github.com/real-Elysia886/Todo-Tree-Next) #4

> 基于 **Next.js** 构建的树形待办事项应用，支持无限嵌套子任务和 Markdown 富文本描述。界面风格参考 **Notion** 与 **Todoist** 的混合体。

<p><img src="https://opengraph.githubassets.com/1/real-Elysia886/Todo-Tree-Next" alt="Todo-Tree-Next" style="max-width:100%;border-radius:8px;"></p>

传统清单应用只支持单层列表，无法体现项目分解结构。作者 **real-Elysia886** 使用 **Next.js App Router** 构建，核心需求是“像思考一样列任务”——父任务下可无限添加子任务。

功能亮点包括：拖拽排序、标签过滤、本地持久化（**IndexedDB**）、以及通过 **WebDAV** 同步到第三方云盘。前端使用 **Tailwind CSS** 和 **Shadcn/ui** 组件库。

已收获 **64** 个 **Star** 与 **3** 个 **Fork**，开发者仍在积极维护，最近一次提交为 3 天前。用户反馈中常见“比主流工具更轻量”的评价。

与 **Todoist** 的层级功能相比，**Todo-Tree-Next** 不设任务数量上限，且完全免费开源，适合项目管理、学习跟踪等场景。

相关链接：
- 项目地址：[real-Elysia886/Todo-Tree-Next](https://github.com/real-Elysia886/Todo-Tree-Next)

## [MikuPlymouth](https://github.com/Thang1191/MikuPlymouth) #5

> 初音未来主题的 **Plymouth** 开机动画包，专为 **NixOS** 及衍生发行版设计。使用 **Nix** 语言编写配置，支持自动合入系统生成器。

<p><img src="https://opengraph.githubassets.com/1/Thang1191/MikuPlymouth" alt="MikuPlymouth" style="max-width:100%;border-radius:8px;"></p>

**Plymouth** 是 **Linux** 下替代 **fbsplash** 的启动画面系统，但社区主题多偏重系统图标。作者 **Thang1191** 为 **Vocaloid** 爱好者，利用 **GIMP** 逐帧绘制出初音未来的像素风加载动画。

项目以 **Nix** 模块形式发布，用户只需在 `configuration.nix` 中添加一行引用即可生效。动画包含 32 帧循环，分辨率为 1920×1080，适配主流 **GRUB** 分辨率。

目前获得 **39** 个 **Star**，虽规模不大，但已成为 **NixOS** 中文社区美化入门教程的推荐案例。**Forks** 为 **1**，表明项目成熟度较高。

与 **plymouth-themes** 仓库中其他主题的区别在于，**MikuPlymouth** 专门优化了 **NixOS** 的 `mkPlymouthTheme` 构建函数，避免手动安装的路径问题。

相关链接：
- 项目地址：[Thang1191/MikuPlymouth](https://github.com/Thang1191/MikuPlymouth)

## [mercury-mcp](https://github.com/norika1207-lab/mercury-mcp) #6

> 一个轻量的 **Model Context Protocol (MCP)** 服务端实现，允许开发者快速将任意 **LLM** 接入支持 MCP 的客户端（如 **Claude**、**Continue** 等）。

<p><img src="https://opengraph.githubassets.com/1/norika1207-lab/mercury-mcp" alt="mercury-mcp" style="max-width:100%;border-radius:8px;"></p>

随着 **MCP** 协议逐渐成为 AI Agent 工具调用的标准接口，现有实现多偏重完整框架，部署较繁琐。**mercury-mcp** 定位为“最小可用”的 **Python** 参考实现，核心仅依赖 `uvicorn` 和 `pydantic`。

服务端提供 **标准输入/输出 (stdio)** 与 **HTTP** 两种通信模式，内建了 **Prompt**、**Resource**、**Tool** 三种原型的示例路由。开发者只需继承基类并注册函数即可发布 MCP 服务。

项目上线一周获 **27** 个 **Star** 与 **9** 个 **Forks**，**Fork** 数量相对较高，说明被大量用于二次开发。**norika1207-lab** 还在 `Discussions` 中贴出了与 **LangChain** 集成的教程。

与 **fastmcp** 等同类库相比，**mercury-mcp** 压缩了自动配置功能，强制开发者显式定义 Schema，更适合教学与审计敏感场景。

相关链接：
- 项目地址：[norika1207-lab/mercury-mcp](https://github.com/norika1207-lab/mercury-mcp)
