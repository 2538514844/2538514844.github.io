## [RoguePlanet](https://github.com/MSNightmare/RoguePlanet) #1

> 一款开源的 rogue-like 游戏引擎，提供网格地图生成、回合制战斗与物品系统，支持动态扩展与自定义 mod 加载。

**RoguePlanet** 由独立开发者 **MSNightmare** 发布，旨在为 rogue-like 游戏爱好者提供一个轻量、可扩展的底层框架。项目使用 **C++** 编写，核心聚焦于程序化地图生成、随机遭遇与装备体系，降低独立开发者制作同类游戏的起步门槛。

<p><img src="https://opengraph.githubassets.com/1/MSNightmare/RoguePlanet" alt="RoguePlanet" style="max-width:100%;border-radius:8px;"></p>

项目目前收获 **156 Stars** 与 **52 Forks**，社区活跃度较高。它区别于同类引擎（如 libtcod）的关键在于设计了插件式 Mod 加载系统，允许开发者在运行时动态注入自定义怪物、物品与规则，无需重新编译。

在性能方面，**RoguePlanet** 支持 80×50 网格的流畅渲染与 AI 路径计算。其低耦合架构适合作为教学范例或快速原型工具，尤其适合对复古 roguelike 玩法感兴趣的开发者。

- 项目地址：[MSNightmare/RoguePlanet](https://github.com/MSNightmare/RoguePlanet)

## [loom](https://github.com/valkor-ai/loom) #2

> 一个基于 TypeScript 的轻量级可视化调试工具，专为前端实时数据流设计，支持 GraphQL、WebSocket 与事件总线追踪。

**loom** 由 **valkor-ai** 团队推出，主要解决前端应用中数据流不透明、调试困难的问题。传统的 `console.log` 或断点调试无法直观展示异步时序与状态变化，**loom** 通过嵌入面板，将应用内事件流以时间线形式呈现。

<p><img src="https://opengraph.githubassets.com/1/valkor-ai/loom" alt="loom" style="max-width:100%;border-radius:8px;"></p>

核心功能包括自动捕获 `fetch`、`WebSocket` 消息与 `useReducer` 状态变更，并以图形化方式绘制依赖链。项目发布后获得 **103 Stars**，社区对其实时追踪与性能开销低的特性反响积极。

相比 **React DevTools** 等成熟工具，**loom** 最大亮点在于协议无关——不只绑定 React，可为任何 **TypeScript** 项目增加可观测性。安装仅需一个 `<script>` 标签，适合中小型团队快速集成。

- 项目地址：[valkor-ai/loom](https://github.com/valkor-ai/loom)

## [ai-video-agent](https://github.com/xuanyuanzhifeng/ai-video-agent) #3

> 基于 AI 多模态智能体的视频内容分析平台，支持视频切片、物体识别、语音转录与结构化报告生成。

**ai-video-agent** 由 **xuanyuanzhifeng** 开发，目标是为视频分析提供端到端解决方案。它内置 **Whisper** 语音识别、**YOLO** 物体检测与 **CLIP** 语义索引，用户只需上传视频即可获得结构化摘要。

<p><img src="https://opengraph.githubassets.com/1/xuanyuanzhifeng/ai-video-agent" alt="ai-video-agent" style="max-width:100%;border-radius:8px;"></p>

项目采用 **TypeScript** 编写，前后端一体化设计，支持 `Docker` 一键部署。当前 **47 Stars** 与 **17 Forks** 表明在开发者社区中已有一定关注度，尤其适合需要批量处理录像的安防、媒体与教育场景。

与 **Google Video AI** 等云服务不同，**ai-video-agent** 完全本地化运行，数据隐私可控。其智能体架构允许用户通过配置文件串联不同 AI 模型，实现如“检测到人物后自动截取片段”的复合流程。

- 项目地址：[xuanyuanzhifeng/ai-video-agent](https://github.com/xuanyuanzhifeng/ai-video-agent)

## [Gothic1Remake-Trainer](https://github.com/bytemarinereactor/Gothic1Remake-Trainer) #4

> 《哥特王朝 1 重制版》专用修改器，支持角色属性、物品、无敌模式等实时修改，使用 C++ 编写，注入机制稳定。

**Gothic1Remake-Trainer** 由 **bytemarinereactor** 针对这款经典游戏的 2026 年重制版开发。由于重制版采用新引擎，此前修改器无法兼容，该工具填补了玩家快速调试游戏体验的需求。

<p><img src="https://opengraph.githubassets.com/1/bytemarinereactor/Gothic1Remake-Trainer" alt="Gothic1Remake-Trainer" style="max-width:100%;border-radius:8px;"></p>

功能涵盖无限生命、无负重限制、技能点重置与快速传送。项目使用内存读写与 `Detour` 钩子实现，兼容 Steam 当前最新版本。尽管 **Stars 30** 不多，但零 Forks 表明作者一人维护，且源代码干净可读。

此类修改器通常有被反作弊系统误报风险，但 **Gothic1Remake-Trainer** 声明仅用于单机离线模式。对于希望深度体验剧情而不受资源限制的玩家来说，这是一个轻量级选择。

- 项目地址：[bytemarinereactor/Gothic1Remake-Trainer](https://github.com/bytemarinereactor/Gothic1Remake-Trainer)

## [MapGoGoGo](https://github.com/ImGoodBai/MapGoGoGo) #5

> 地图数据批量处理与可视化工具，支持 OSM 数据导入、图层编辑与 GeoJSON 导出，基于 TypeScript 构建 Web 界面。

**MapGoGoGo** 由 **ImGoodBai** 发布，面向地理信息从业者与 GIS 爱好者。它提供拖拽式操作界面，可一键转换 `shp`、`geojson` 等格式，并叠加多个图层生成自定义地图。

<p><img src="https://opengraph.githubassets.com/1/ImGoodBai/MapGoGoGo" alt="MapGoGoGo" style="max-width:100%;border-radius:8px;"></p>

项目使用 **MapLibre GL** 作为渲染引擎，前端完全在浏览器内运行，无需后端服务。当前 **28 Stars**，社区反馈集中在数据加载性能与导出清晰度。其与众不同的是集成 **Overpass API**，可直接查询 OpenStreetMap 兴趣点并实时渲染。

对于需要本地处理地图数据的地理博主或小型规划团队，**MapGoGoGo** 提供了一种避开商业软件的免费替代方案。未来计划加入路径分析与 3D 建筑显示。

- 项目地址：[ImGoodBai/MapGoGoGo](https://github.com/ImGoodBai/MapGoGoGo)

## [AgenticMedChem](https://github.com/xche-YDS/AgenticMedChem) #6

> 基于 AI Agent 的药物化学分子生成与优化框架，集成分子对接、ADMET 预测与多目标进化算法。

**AgenticMedChem** 由 **xche-YDS** 团队开源，目标是加速先导化合物优化流程。该框架利用 **RDKit** 进行分子操作，并引入强化学习 Agent 自主探索化学空间，搜索满足特定药效团与毒性要求的分子。

<p><img src="https://opengraph.githubassets.com/1/xche-YDS/AgenticMedChem" alt="AgenticMedChem" style="max-width:100%;border-radius:8px;"></p>

项目核心是“合成可行性”评分与 **AutoDock Vina** 对接流水线，Agent 可迭代数千代寻找优化解。虽然 **Stars 21** 尚属早期，但 **2 Forks** 和文档清晰度暗示其专业性较强，适合计算化学研究人员。

与 **DeepChem** 等通用框架相比，**AgenticMedChem** 更聚焦于药物化学家的交互——提供 `Jupyter Notebook` 界面，可实时可视化分子结构变化。运行需 Python 3.9+ 与 `CUDA` 支持。

- 项目地址：[xche-YDS/AgenticMedChem](https://github.com/xche-YDS/AgenticMedChem)

## [GPT-Relay-Codex-Plugin-](https://github.com/Toolsai/GPT-Relay-Codex-Plugin-) #7

> 为 OpenAI GPT 模型设计的 Relay 与 Codex 中间件插件，支持自定义上下文路由与多模型切换。

**GPT-Relay-Codex-Plugin-** 由 **Toolsai** 开发，解决用户在多 GPT 模型之间切换时频繁修改 prompt 与 API 端点的痛点。它提供一个轻量级中间层，可配置负载均衡、失败重试与角色预设。

<p><img src="https://opengraph.githubassets.com/1/Toolsai/GPT-Relay-Codex-Plugin-" alt="GPT-Relay-Codex-Plugin-" style="max-width:100%;border-radius:8px;"></p>

项目基于 **JavaScript** 编写，可作为 `Express` 中间件或独立服务运行。当前 **19 Stars**，社区贡献了多个语言模型的后端适配器（包括 **Claude** 与 **Gemini**）。其“Codex”部分支持自动补全上下文窗口管理，防止长对话超 token 限制。

对于企业级多模型接入场景，**GPT-Relay-Codex-Plugin-** 提供了最小的侵入式集成方案，开发者无需修改原有调用代码即可切换底层模型供应商。

- 项目地址：[Toolsai/GPT-Relay-Codex-Plugin-](https://github.com/Toolsai/GPT-Relay-Codex-Plugin-)

## [open-impact-ej](https://github.com/kauzone11/open-impact-ej) #8

> 开源教育影响评估框架，用于量化学习项目在知识、技能与态度三个维度的长期效果。

**open-impact-ej** 由 **kauzone11** 发布，目标是为非政府组织与教育机构提供免费评估工具。它内置标准化问卷模板、统计分析与可视化报告生成，帮助项目管理者追踪干预效果。

<p><img src="https://opengraph.githubassets.com/1/kauzone11/open-impact-ej" alt="open-impact-ej" style="max-width:100%;border-radius:8px;"></p>

项目采用 **TypeScript** 构建前端，后端依赖 **PostgreSQL** 与 **Chart.js**。虽然 **Stars 7** 较少，但代码结构清晰，文档包含完整的部署指南。其核心特点是预置“Kirkpatrick 模型”四级评估逻辑，可输出对比实验组与对照组的结果。

对希望降低数据采集成本的教育公益组织而言，**open-impact-ej** 提供了一种符合隐私法规（GDPR 兼容）的本地部署方案。后续版本计划加入自然语言处理的开放题分析。

- 项目地址：[kauzone11/open-impact-ej](https://github.com/kauzone11/open-impact-ej)

## [Dirlens](https://github.com/LTX128/Dirlens) #9

> Python 目录结构可视化与分析工具，支持导出为 Markdown、JSON 与树形图，内置文件类型统计与大小分布。

**Dirlens** 由 **LTX128** 开发，用于快速生成项目文件结构概览。它递归扫描指定目录，并基于文件扩展名、大小和修改时间生成可视化报告，方便文档编写或仓库审计。

<p><img src="https://opengraph.githubassets.com/1/LTX128/Dirlens" alt="Dirlens" style="max-width:100%;border-radius:8px;"></p>

安装仅需 `pip install dirlens`，命令 `dirlens /path` 即可输出。当前 **6 Stars**，社区反馈侧重输出格式完整度（支持各主流文件类型图标）。与 **tree** 命令相比，**Dirlens** 额外提供饼图统计与大小排行榜，适合大仓库性能瓶颈定位。

对于开发者撰写 README 或整理归档文件，**Dirlens** 能自动忽略 `.git`、`node_modules` 等常见排除项。未来计划增加 `.gitignore` 模式匹配与差异对比功能。

- 项目地址：[LTX128/Dirlens](https://github.com/LTX128/Dirlens)
